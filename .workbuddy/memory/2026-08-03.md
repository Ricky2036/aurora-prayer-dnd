## Aurora Phone 高保真交互原型（M1-M6 全部完成）

**项目**：安卓打孔屏机身 × iOS 界面语言的网页端手机原型。Vue 3 + Vite + Pinia，工作区即工程根目录。
**运行**：`npm run dev`（托管 Node 22，端口 5175 常驻后台任务 a4Iibg）；`npm run build` → dist（base './'，任意静态路径可开）。

### 架构要点（复用时看）
- **状态机**：systemStore 基础层(lock/home/app) + 正交叠层(NC/CC/appLibrary，各带 status+progress 0..1)。手势 dragging → 松手 settling → spring 推进 → settle 终态；requestCloseOverlay → closing → spring 播完才 closed。
- **手势/spring**：useSwipeGesture（Pointer Events、方向锁定 8px、环形缓冲速度采样、松手速度注入弹簧初速度）；useSpring（半隐式欧拉，三档预设，settle 阈值 0.02/0.001，初速度上限 ±6）。
- **驱动共享**：叠层 spring 驱动在 ScreenView 创建并经 composables/driverRegistry.js 共享；AppLibrary 反向手势经 getDriver 接管同一 spring（防双 spring 打架）。
- **Hero 动画**：useHeroTransition FLIP（transform+borderRadius，ease cubic-bezier(0.32,0.72,0,1)，430ms），图标 rect 经 utils/screenRef + dom.js 换算（注意舞台整体缩放）。
- **新增应用** = config/apps.js 注册项 + registry.js 组件；**新增通知** = notificationsStore.push。

### 踩过的坑（重要）
1. **Vue 模板只自动解包顶层 ref**：composable 返回对象里的 computed 必须解构后再绑定，否则样式静默失效（hero 关闭曾因此卡死）。
2. **v-if 内的手势绑定失效**：useSwipeGesture 在 onMounted 绑定，v-if 元素挂载时还不存在 → 用 v-show（AppLibrary 反向手势案例）。
3. **dev server 输出别接 `| head`**：head 关管道后 vite 收 SIGPIPE 闪退，两次中招。
4. **锁屏必须自带不透明壁纸**：否则与桌面元素透视重叠。
5. **拖拽后 350ms 内抑制 click**：热区拖拽松手会紧随 click 事件，需时间戳防误触 toggle。
6. **aw-content 必须 inset:0 全出血**：安全区 padding 交给各应用，否则边缘露出 hero 主题色底。
7. **状态栏/Home 条随应用背景变色**：浅色应用内切深色（DARK_BG_APPS 例外名单）。

### 关键 bug 与根因（复用价值高）
1. **窄热区手势失效**：pointermove 只监听元素自身，22px 侧缘第一步移出就断。**修法：pointerdown 挂元素，move/up/cancel 挂 window（capture 阶段），down 时绑定、up 时解绑**。边缘手势标准做法。
2. **卡片卡死（缩放半态悬浮）**：hero close 依赖 transitionend，事件丢失就永久卡住。**修法：useHeroTransition 加看门狗 setTimeout(duration+120) 强制完成**。凡依赖 transitionend 的动画都要配看门狗。
3. **pointercancel 丢进度**：旧实现 cancel 只复位标志 → 跟手进度悬空。**修法：cancel 视同 release（velocity=0 走完整 onRelease）**。
4. **v-if 元素上的 click 冒泡陷阱**：click 处理器内 v-if 卸载 e.target，冒泡到父级时 target.closest() 失效 → 父级误判区域外点击（锁屏堆叠点了展不开）。**修法：内层 @click.stop**。
5. **叠层根元素常驻**：v-if 导致 useSwipeGesture 挂不上 → 改常驻 + visibility/pointerEvents 随状态切换；driver 经 driverRegistry 共享给 NC/CC 面板挂 closeGesture（打开后上滑关闭）。

### 安卓控制中心移植要点（android_control_center.tsx → Vue）
- 布局引擎 `src/components/system/cc/ccLayout.js`：packLayout / computeDisplayLayout（swap 模式：1v1 交换 / 垂直隧道打压 / 空位落户）/ FLIP record+apply
- 拖拽 HTML5 DnD + 120ms 防抖雷达；**Playwright 鼠标模拟不触发 HTML5 DnD，验证要 dispatch 合成 DragEvent（dataTransfer 必须 new DataTransfer()）**

### 再修正：CC 编辑模式 FLIP 位移动效丢失
- **根因**：① watch(displayLayout) 用默认 flush 'pre' + nextTick，快速连续推演时回调被合并、且 applyFlip 首跑后 `store.positions=null` 使后续直接 return → 动画只在第一次格子变化播放；② 取消拖拽（dragend 不 drop）时 dragState=null → displayLayout 返回 layout（引用不变）→ watch 不触发 → 卡片跳回无补间；③ WAAPI 动画叠加无取消。
- **修法**：watch 改 `{ flush: 'post' }` 直接 applyFlip（DOM 更新后同步，等同 React useLayoutEffect）；onDrop/onDragEnd 内 recordPositions 后手动 `nextTick(() => applyFlip(...))` 补落位/回位补间；applyFlip 内 `node.getAnimations().forEach(a => a.cancel())` 防叠加。
- **验证**：debug-flip.mjs 合成 DragEvent 拖拽：seg1→2 个 FLIP、seg2→3 个 FLIP、drop 落位 flashlight x 385→560、dragend 取消回位 sound x 复原 + 4 次 animate（含回位补间）。
- **经验**：Playwright mouse 拖动不触发 HTML5 DnD，验证必须 dispatch 合成 DragEvent（dataTransfer 用 new DataTransfer()，dragstart 后须 waitForTimeout 让 setTimeout(0) 置 dragState，否则连续 dragover 全被忽略）。

### 再修正：CC resize 1x1→2x1 其他图标位移动画缺失
- **根因**：上轮 FLIP 修复时漏改 — `watch(displayLayout)` 里 `if (resizingId.value === null)` 把 resize 路径整体跳过，伸缩重排时 packLayout 改了邻居位置但 FLIP 不跑。
- **修法**：去掉 resizingId 判断（FLIP 在拖拽推演/落位/伸缩重排都播）；被缩放卡片自身的宽度动画由 CSS `transition: width 350ms` 承担，与 FLIP transform 不冲突。同时确认保留 `{ flush: 'post' }`（pre 会在 DOM 更新前读旧位置 → 无位移）。
- **验证**：debug-resize.mjs mouse 拖手柄右移 70px → animCount 18（sound/bluetooth 等 `translate(-87px)` 左移一列；hotspot/darkMode/scan 等 `translate(262px,-74px)` 跨行下移）；flashlightW 148（1x1→2x1 成功）；拖拽 FLIP 回归通过（seg1=2、seg2=5）。
